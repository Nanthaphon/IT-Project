# ย้ายชุด UI "Harbor" เข้าโปรเจคนี้

ชุด design system จาก **IT Asset Management** — ตาราง · modal · badge · ฟอร์ม · ไทม์ไลน์
พร้อมชุดสีและกฎการออกแบบ

เอกสารนี้เขียนสำหรับโปรเจคที่**มีหน้าใช้งานอยู่แล้ว** ไม่ใช่เริ่มจากศูนย์
วางไฟล์นี้ไว้ที่ root ของโปรเจคปลายทางได้เลย ทำตามได้จบในตัว

---

## 0. เช็คก่อนว่าเข้ากันได้ไหม

รันในโปรเจคปลายทาง

```bash
node -p "const p=require('./package.json');
  JSON.stringify({react:p.dependencies.react, lucide:p.dependencies['lucide-react'],
  tw:(p.devDependencies||{}).tailwindcss, ts:(p.devDependencies||{}).typescript},null,1)"
```

| เจออะไร | ต้องทำอะไร |
|---|---|
| React 18 / 19 | ไม่ต้องทำอะไร |
| ไม่มี `lucide-react` | `npm i lucide-react` |
| `tailwindcss` ^3 | ใช้ข้อ 2 **ไม่ต้องอัปเป็น v4** |
| `tailwindcss` ^4 | ใช้ข้อ 2 (ทางเลือก v4) |
| ไม่มี tailwind | หยุดก่อน — ต้องประเมินใหม่ว่าคุ้มไหม |
| มี `typescript` | ดูข้อ 4 |

ฐานข้อมูลไม่เกี่ยว — ชุดนี้ไม่มีไฟล์ไหนแตะฐานข้อมูลเลย (Supabase / Firebase / REST ก็ใช้ได้หมด)

### Tailwind v4 — แปะลงหัว `index.css`

เปลี่ยนรูปแบบเป็น `--color-<ชื่อ>-<เฉด>: <ค่า>;` ในบล็อก `@theme { }`
หรือรันสคริปต์ที่มีอยู่ในโปรเจคต้นทาง: `node scripts/export-palette.mjs`

### ชื่อ token ไม่ตรงกับสี — ตั้งใจ

`clay` เคยเป็นสีส้มอิฐ ตอนนี้เป็น teal · `olive` เคยเป็นเขียวมะกอก ตอนนี้เป็นเขียวน้ำทะเล
ทำแบบนี้เพื่อเปลี่ยนธีมได้โดยไม่ต้องแตะคลาสในคอมโพเนนต์นับพันจุด

**ถ้าโปรเจคนี้อยากได้ชื่อที่สื่อบทบาท** (`brand-*` `success-*` `danger-*`)
ให้ rename **ตอนนี้เลย** ก่อนเขียนหน้าแรก — ทำทีหลังแพงกว่ามาก

## 3. เปลี่ยนโทนสีให้เป็นของโปรเจคนี้

แก้ 3 ที่ ให้ค่าตรงกันทั้งหมด

| ที่ | อะไร |
|---|---|
| `tailwind.config.js` (หรือ `@theme`) | ชุดสีหลัก 48 ค่า |
| `src/ui/theme.js` → `BRAND` | สี 5 ค่าที่ใช้ผ่าน `style={{}}` (inline style ใช้คลาส Tailwind ไม่ได้) |
| `src/utils/printTheme.js` → `P` / `TONE` | หน้าพิมพ์เปิดใน window ใหม่ที่ไม่มี Tailwind |

เริ่มจากเลือกสีฐาน 5–6 ตัว แล้วไล่โทนอ่อน/เข้มรอบ ๆ ไม่ต้องคิดเองทั้ง 48 ค่า

### ตรวจคอนทราสต์ก่อนใช้จริง

สีที่สวยบนจอ อาจอ่านไม่ออกเมื่อเป็นตัวอักษรเล็ก เคยพลาดมาแล้วทั้งสองแบบ

- `#52ab98` เป็นพื้นปุ่มตัวอักษรขาว = **2.75:1** ไม่ผ่าน → ต้องใช้ `#3D8072` (4.64:1)
- ป้ายสถานะบนกระดาษ 9.5px = **2.78:1** บนจอใช้ได้ บนกระดาษอ่านแทบไม่ออก

เกณฑ์: ตัวอักษรปกติ **≥ 4.5:1** · ป้ายเล็ก 10px ยิ่งต้องเผื่อ

## 4. ถ้าโปรเจคเป็น TypeScript

ไฟล์ที่ก๊อปเป็น `.jsx` / `.js` ล้วน เลือกทางใดทางหนึ่ง

1. **ตั้ง `"allowJs": true`** ใน `tsconfig.app.json` — ใช้ปนกันได้เลย เร็วสุด
2. **เปลี่ยนเป็น `.tsx` แล้วใส่ type** — สะอาดกว่า เริ่มจาก `earthUI.jsx` ตัวเดียวก่อนได้

## 5. ย้ายทีละส่วน ไม่ต้องรื้อทั้งระบบ

1. **ใส่ชุดสี** (ข้อ 2) — ยังไม่มีอะไรเปลี่ยนหน้าตา เพราะยังไม่มีใครใช้คลาสใหม่
2. **ก๊อปไฟล์** (ข้อ 1)
3. **เขียนหน้าถัดไปด้วย `ListPage`** — ได้ของใหม่โดยไม่แตะของเก่า
4. **หน้าเก่าค่อยย้าย** ตอนมีเหตุต้องแก้อยู่แล้ว

แบบนี้ไม่มีจังหวะที่ระบบพังทั้งก้อน และเห็นผลตั้งแต่หน้าแรกที่ย้าย

### หน้ารายการทำยังไง

`ListPage` รับแค่ 3 อย่าง: `columns` + `rowActions` + `toolbar`
ทุกหน้าเป็น controlled component — ค้นหา/กรอง/แบ่งหน้า/การเลือก เป็น state ของหน้าแม่
**ห้ามสร้าง state ซ้ำในคอมโพเนนต์** จะเกิด "ความจริงสองชุด" ดีบักยากมาก

ดูตัวอย่างที่ `components/licenses/LicenseListPage.jsx` (~110 บรรทัดทั้งหน้า)

## 6. กฎที่ต้องคุม — สำคัญกว่าตัวสี

| เรื่อง | กฎ |
|---|---|
| ขนาดตัวอักษร | **9 ค่าเท่านั้น** `10 · 11 · 12 · 13 · 14 · 15 · 19 · 22 · 30` ห้ามค่าครึ่งพิกเซล |
| ความหนา | **`font-normal` กับ `font-medium` เท่านั้น** ห้าม semibold / bold |
| ไอคอน | `lucide-react` เท่านั้น · `strokeWidth={2}` ค่าเดียว · ห้ามเขียน `<svg>` เอง · ห้ามใช้ emoji แทนไอคอน |
| การ์ด | `rounded-2xl` + `border-stone-200/60` + เงาบาง |
| Badge | `rounded-lg` + พื้นอ่อน **ไม่มีขอบ** + `font-medium` |
| ตาราง | หัวตารางไม่มีพื้น · แถว `py-4` · เส้นคั่นบาง |
| สถานะ | ใช้ `statusTone()` เสมอ ห้ามเขียนสีที่คอมโพเนนต์ |
| หน้า | เต็มความกว้าง `p-4 lg:p-5` · ไม่จัดกึ่งกลางด้วย `max-w-*` · ไม่มีหัวเรื่องซ้ำกับแถบบน |
| **ข้อความไทยในตาราง** | ต้อง `whitespace-nowrap` — ไทยไม่มีเว้นวรรค เบราว์เซอร์ตัดกลางคำได้ (`โน้ตบุ๊ค` → `โน้ต`/`บุ๊ค`) |

ระบบต้นทางเคยมีขนาดตัวอักษร **30 ค่า** และ `strokeWidth` **12 ค่า**
ตอนนั้นสีตรงธีมหมดแล้วแต่ยังดูไม่เป็นชุดเดียวกัน จนมาคุมสองอย่างนี้ถึงหาย

## 7. ช่วงที่มีสองชุดปนกันจะเห็นอะไร

3 อย่างนี้จะตำตาที่สุด ถ้าจะแก้ทั้งระบบรวดเดียวก็คุ้มกว่าไล่แก้ทีละหน้า

1. **ความหนาตัวอักษร** — ของเดิมมักใช้ `font-semibold`/`font-bold` ชุดใหม่มีแค่ `font-medium`
2. **มุมโค้ง** — การ์ดชุดใหม่ `rounded-2xl` ปุ่ม/ช่องกรอก `rounded-xl`
3. **ความหนาเส้นไอคอน** — ชุดใหม่ `strokeWidth={2}` ค่าเดียวทั้งระบบ

## 8. สองอย่างที่ควรทำตั้งแต่วันแรก

### Dev harness — ดูหน้าได้โดยไม่ต้องล็อกอิน

สร้าง `xxx-preview.html` ที่ root + `src/xxx-preview.jsx` แล้วเปิด `/xxx-preview.html`
Vite build เฉพาะ `index.html` ไฟล์พวกนี้จึงไม่ขึ้น production

งาน UI ทั้งหมดของระบบต้นทางตรวจผ่าน harness ไม่ต้องแตะฐานข้อมูลจริง
และเป็นที่เดียวที่ทำให้จับบั๊กแบบ "ข้อความไทยตกบรรทัดตอนคอลัมน์โดนบีบ" ได้

### สคริปต์ไล่หาคลาสสีที่ไม่มีนิยาม

Tailwind จะ**ไม่สร้างคลาส**ที่ไม่มีค่าใน config — เป็นคลาสตายที่ไม่มี error ให้เห็น
ระบบต้นทางเคยมี `text-clay-950` กับ `hover:text-olive-900` หลุดอยู่
ป้ายตัวเลขบน sidebar เลยอ่านไม่ออกอยู่นานโดยไม่มีใครรู้

เขียนสคริปต์เทียบคลาสที่ใช้จริงกับค่าที่นิยามไว้ แล้วใส่ใน CI หรือรันก่อน commit
