# ยกชุด UI นี้ไปใช้กับโปรเจคอื่น

คู่มือย้าย design system ของ IT Asset Management ไปใช้ที่อื่น พร้อมเปลี่ยนโทนสี

- **เริ่มโปรเจคใหม่** → อ่านข้อ 1–7 ตามลำดับ
- **โปรเจคที่ขึ้นโครงไปแล้ว** → ข้ามไปอ่าน [ข้อ 9](#9-กรณีโปรเจคที่ขึ้นโครงไปแล้ว) ก่อน แล้วค่อยย้อนมาข้อ 2

ตรวจตัวเลขทั้งหมดในเอกสารนี้จากโค้ดจริงเมื่อ 23 ก.ย. 2569

---

## สรุปสั้น

ชั้น design system **ไม่มีไฟล์ไหนแตะ Firebase เลย** พึ่งแค่ React + lucide-react + Tailwind v4
ก๊อป 12 ไฟล์ (~1,960 บรรทัด) ไปวางแล้วใช้ได้เลย

สิ่งที่ทำให้หน้าตาเป็นชุดเดียวกันคือ **กฎ** ไม่ใช่สี — อ่าน `CLAUDE.md` หัวข้อ Design System
แล้วยกกฎไปด้วย ไม่งั้นโปรเจคใหม่จะเพี้ยนภายในเดือนเดียว

## 1. สิ่งที่ต้องลง

```bash
npm create vite@latest my-app -- --template react
cd my-app
npm i lucide-react
npm i -D tailwindcss @tailwindcss/vite
```

`vite.config.js`

```js
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({ plugins: [react(), tailwindcss()] })
```

> ต้องเป็น **Tailwind v4** เท่านั้น — ธีมทั้งชุดใช้บล็อก `@theme` ซึ่ง v3 ไม่มี

## 3. เปลี่ยนโทนสี

### ตอนนี้ต้องแก้ 3 ไฟล์

**1) `src/index.css` — บล็อก `@theme`** (ตัวหลัก 48 ค่า)

ไม่ต้องคิดเองทั้ง 48 ค่า เลือกสีฐาน 5–6 ตัวก่อน แล้วไล่ไล่โทนอ่อน/เข้มรอบ ๆ

```css
@theme {
  --color-clay-600: #2B6777;   /* สีแบรนด์ — ปุ่ม ไฮไลท์ sidebar */
  --color-clay-700: #225462;   /* hover */
  --color-clay-900: #12303A;   /* พื้น sidebar */
  --color-sand-50:  #F7F9FA;   /* พื้นหน้าจอ */
  --color-olive-600:#3D8072;   /* สถานะสำเร็จ */
  /* ... */
}
```

> **ชื่อ token ไม่ต้องตรงกับสี** — `clay` เคยเป็นสีส้มอิฐ ตอนนี้เป็น teal
> ตั้งใจไม่ rename เพื่อไม่ต้องแตะคลาสในคอมโพเนนต์นับพันจุด
> ถ้าโปรเจคใหม่อยากได้ชื่อที่สื่อบทบาท (`brand-*` `success-*` `danger-*`)
> ให้ rename ตอนเริ่มเลย ทำทีหลังแพงกว่ามาก

**2) `src/ui/theme.js` — `BRAND`**

มีสี hardcode ซ้ำกับ `index.css` 5 ค่า ใช้อยู่ **43 จุด** ผ่าน `style={{}}`
(จำเป็น เพราะ inline style ใช้คลาส Tailwind ไม่ได้)

**3) `src/utils/printTheme.js` — `P` และ `TONE`**

หน้าพิมพ์เปิดใน window ใหม่ที่ไม่มี Tailwind จึงต้องเขียนค่าสีตรง ๆ

### ตรวจคอนทราสต์ก่อนใช้จริง

สีที่ดูดีบนจอ อาจอ่านไม่ออกตอนเป็นตัวอักษรเล็ก เคยเจอมาแล้วทั้งสองแบบ:

- `#52ab98` เป็นพื้นปุ่มตัวอักษรขาว = 2.75:1 — ไม่ผ่าน ต้องใช้ `#3D8072` (4.64:1)
- ป้าย "ตัดจำหน่าย" บนกระดาษ 9.5px = 2.78:1 — บนจอใช้ได้ บนกระดาษอ่านแทบไม่ออก

เกณฑ์: ตัวอักษรปกติต้อง **≥ 4.5:1** · ป้ายเล็ก (10px) ยิ่งต้องเผื่อ

## 5. กฎที่ต้องยกไปด้วย

ย่อจาก `CLAUDE.md` — ฉบับเต็มอยู่ในหัวข้อ Design System

| สถานะ | ใช้ `statusTone()` เสมอ ห้ามเขียนสีที่คอมโพเนนต์ |
| หน้า | เต็มความกว้าง `p-4 lg:p-5` · ไม่จัดกึ่งกลางด้วย `max-w-*` · ไม่มีหัวเรื่องซ้ำกับแถบบน |
| ข้อความไทยในตาราง | ต้อง `whitespace-nowrap` — ไทยไม่มีเว้นวรรค เบราว์เซอร์ตัดกลางคำได้ |

**เหตุผลที่ต้องคุมขนาด/ความหนา:** ระบบนี้เคยมีขนาดตัวอักษร 30 ค่า และ `strokeWidth` 12 ค่า
ทุกหน้าสีตรงธีมหมดแต่ยังดูไม่เป็นชุดเดียวกัน จนมาคุมสองอย่างนี้ถึงหาย

## 6. เครื่องมือที่ควรยกไปด้วย

**Dev harness** — ดูหน้าได้โดยไม่ต้องล็อกอิน ไม่ต้องต่อฐานข้อมูล

สร้าง `xxx-preview.html` ที่ root + `src/xxx-preview.jsx` แล้วเปิด `localhost:5173/xxx-preview.html`
Vite build เฉพาะ `index.html` ไฟล์พวกนี้จึงไม่ขึ้น production

คุ้มมาก — งาน UI ทั้งหมดในโปรเจคนี้ตรวจผ่าน harness ไม่ต้องแตะฐานข้อมูลจริง
และเป็นที่เดียวที่ทำให้จับบั๊กอย่าง "ข้อความไทยตกบรรทัดตอนคอลัมน์โดนบีบ" ได้

**สคริปต์ตรวจอัตโนมัติ** ที่มีอยู่แล้วและยกไปใช้ต่อได้

```bash
npm run check:needs    # ตรวจ mapping ของ Firestore (เฉพาะโปรเจคนี้)
```

แนะนำให้เขียนเพิ่มอีกตัวสำหรับโปรเจคใหม่: **ไล่หาคลาสสีที่ไม่มีนิยาม**
เคยเจอ `text-clay-950` กับ `hover:text-olive-900` ที่ Tailwind ไม่สร้างคลาสให้
เพราะไม่มีใน `@theme` — เป็นคลาสตายที่ไม่มี error ให้เห็น ป้ายบน sidebar เลยอ่านไม่ออกอยู่นาน

## 8. ข้อเสนอให้ทำก่อนยก (ยังไม่ได้ทำ)

**เปลี่ยนสีจากไฟล์เดียว** — ย้ายสีไปไว้ใน `src/ui/palette.js` เป็น JS ธรรมดา

ควรทำ**ก่อน**ยกไปโปรเจคใหม่ ไม่งั้นโปรเจคที่ 2 จะลอกปัญหาสีซ้ำซ้อนไปด้วย

## 9. กรณีโปรเจคที่ขึ้นโครงไปแล้ว

คู่มือข้อ 1–7 เขียนสำหรับ **เริ่มโปรเจคใหม่** ถ้าโปรเจคมีหน้าตาของตัวเองไปแล้ว
วางไฟล์นี้ไว้เฉย ๆ ทำตามไม่ได้ทันที เพราะข้อ 1 บังคับ Tailwind v4

### ตรวจ 4 อย่างก่อน

```bash
node -p "const p=require('./package.json');
  JSON.stringify({react:p.dependencies.react, lucide:p.dependencies['lucide-react'],
  tw:(p.devDependencies||{}).tailwindcss, ts:(p.devDependencies||{}).typescript},null,1)"
```

| เจออะไร | แปลว่า |
|---|---|
| React 18/19 | ผ่าน |
| ไม่มี `lucide-react` | `npm i lucide-react` |
| `tailwindcss` ^3 | **ไม่ต้องอัปเป็น v4** — ดูทางเลือก ก |
| ไม่มี tailwind เลย | งานใหญ่ ต้องคิดใหม่ว่าคุ้มไหม |
| มี `typescript` | ไฟล์ที่ก๊อปเป็น `.jsx`/`.js` ต้องตั้ง `allowJs` |

### ตัวอย่างจริง — Acc Form Project (ระบบเบิกค่าใช้จ่าย)

| | ค่า | ผล |
|---|---|---|
| React | 19.2.7 | ผ่าน |
| lucide-react | 1.28.0 | ผ่าน (โปรเจคนี้ 1.16) |
| tailwindcss | **3.4.19** | ต้องแปลงธีม — ทางเลือก ก |
| TypeScript | 6.0.2 | ต้องตั้ง `allowJs` |
| ฐานข้อมูล | Supabase | **ไม่เกี่ยว** — design system ไม่แตะฐานข้อมูลเลย |

### ทางเลือก ก — อยู่กับ Tailwind v3 (แนะนำ)

`@theme` เป็นไวยากรณ์ของ v4 ก็จริง แต่ **ชุดสีไม่ได้ผูกกับ v4**
ย้ายค่าสีไปไว้ใน `tailwind.config.js` แทน แล้วคลาสทุกตัวใช้ชื่อเดิมได้หมด
(`bg-clay-600` · `text-stone-400` · `ring-clay-600/15` · `bg-clay-600/[0.08]`)

```bash
# รันในโปรเจค IT Asset แล้วเอาไฟล์ไปวางที่โปรเจคปลายทาง
node scripts/export-palette.mjs > ../ปลายทาง/tailwind.config.js
```

สคริปต์อ่านบล็อก `@theme` จาก `index.css` แล้วแปลงเป็น `theme.extend.colors`
ครบทั้ง 48 ค่า 7 กลุ่ม (clay · sand · ochre · olive · brick · rose · stone)

> `stone` ถูกทับค่าเดิมของ Tailwind ด้วยเทาโทนเย็น — วางใน `extend` ได้เลย
> v3 จะ merge ทับเฉพาะเฉดที่ระบุ

ถ้าโปรเจคปลายทางมี `tailwind.config.js` อยู่แล้ว ให้ก๊อปเฉพาะบล็อก `colors`
ไปรวมกับของเดิม อย่าเขียนทับทั้งไฟล์ (จะทำ `content` กับ plugin เดิมหาย)

### ทางเลือก ข — อัปเป็น Tailwind v4

ได้ `@theme` เหมือนต้นทางเป๊ะ แต่ v4 เปลี่ยนวิธีตั้งค่าและคลาสบางตัว
**ไม่แนะนำสำหรับโปรเจคที่มีหน้าใช้งานอยู่แล้ว** — ไปแตะของที่ทำงานอยู่โดยไม่จำเป็น
ถ้าจะทำจริงค่อยทำเป็นงานแยก ไม่ใช่ทำพร้อมกับย้ายธีม

### เรื่อง TypeScript

ไฟล์ที่ก๊อปเป็น `.jsx`/`.js` ล้วน มี 2 ทาง

1. **ตั้ง `allowJs: true`** ใน `tsconfig.app.json` แล้วใช้ปนกันได้เลย — เร็วสุด
2. **เปลี่ยนเป็น `.tsx` แล้วใส่ type** — สะอาดกว่าแต่ใช้เวลา เริ่มจาก `earthUI.jsx` ตัวเดียวก่อนได้

### ย้ายทีละส่วน ไม่ต้องรื้อทั้งระบบ

หน้าที่มีอยู่แล้วปล่อยไว้ก่อน ค่อย ๆ ย้ายแบบนี้

1. วางชุดสี (ทางเลือก ก) — ยังไม่มีอะไรเปลี่ยนหน้าตา เพราะยังไม่มีใครใช้คลาสใหม่
2. ก๊อป `ui/` + `components/list/` เข้าไป
3. **เขียนหน้าใหม่หน้าถัดไปด้วย `ListPage`** — ได้ของใหม่โดยไม่แตะของเก่า
4. หน้าเก่าค่อยย้ายตอนมีเหตุต้องแก้อยู่แล้ว

แบบนี้ไม่มีจังหวะที่ระบบพังทั้งก้อน และเห็นผลตั้งแต่หน้าแรกที่ย้าย

### สิ่งที่จะดูแปลกตาในช่วงเปลี่ยนผ่าน

ระหว่างที่ยังมีสองชุดปนกัน จะเห็นความต่างชัดสุด 3 อย่าง
เตรียมใจไว้ หรือแก้ 3 อย่างนี้ทั้งระบบก่อนเป็นอันดับแรกก็ได้ — คุ้มกว่าไล่แก้ทีละหน้า

1. **ความหนาตัวอักษร** — ของเดิมมักใช้ `font-semibold`/`font-bold` ชุดใหม่มีแค่ `font-medium`
2. **มุมโค้ง** — การ์ดชุดใหม่เป็น `rounded-2xl` ปุ่ม/ช่องกรอกเป็น `rounded-xl`
3. **ความหนาเส้นไอคอน** — ชุดใหม่ `strokeWidth={2}` ค่าเดียวทั้งระบบ
